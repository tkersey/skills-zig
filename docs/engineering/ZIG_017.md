# Zig 0.17 migration

The only supported compiler is Zig 0.17.0; Zig 0.16 is no longer supported. macOS release binaries target macOS 15
and the baseline ARM64 CPU; Linux keeps each CLI's established target and ABI.
CLI schemas, durable formats, canonical digests, and Ledger replay semantics
do not change with the compiler upgrade.

## Build and dependencies

The root build and standalone Seq build use make-time install admission in
`apps/seq/build_support.zig` and `tools/install_guard.zig`. Every artifact copy
depends on the guard. The shared build helper lives within Seq’s package root so
both build scripts can import the same implementation without escaping a module root. It runs even when configuration is cached and rejects
external prefixes, executable directories, and `DESTDIR`. Release packaging
continues to copy already built artifacts out of repository-local `zig-out/bin`.

The official Translate-C package supplies target-specific `time.h` bindings.
It is pinned by source revision and package hash in both package manifests.
This avoids maintaining handwritten platform ABI declarations or changing
local timezone behavior. `test-seq-time-local` exercises DST and pre-epoch dates
in a separate process with an explicit timezone.

Zlinter is pinned to a revision that no longer depends on ZLS. Its remaining
0.17 compatibility changes are applied by `tools/zlinter_compat.zig` to a separate,
content-addressed generated tree. Each patch requires exactly one source match;
the original package remains unchanged. The patches adapt ZON parsing and
diagnostics, and recognize the new build-path variant. This avoids an unpinned
fork, a second installed compiler for lint, or copied upstream source in this
repository. Upstream source is MIT-licensed and retains its original attribution.
Retire this overlay when a qualified upstream revision includes the fixes.
The patched upstream suite passes all 463 tests. Repository-level probes also
exercise unused declarations, public and cross-module references, and malformed
configuration; generated C imports are covered by the ordinary lint run.

Run helpers pass arguments through at make time. Executables own empty-argument
help behavior. The Linux CAS dispatcher check still executes the installed
sibling layout, rather than a cache artifact with different path semantics.
Unit-test steps use the build runner's test protocol and options such as
`--seed`; they do not add a passthrough argument entry. Zig 0.17's fuzz replay
rejects that entry even when it expands to zero arguments. CLI run helpers
continue to forward arguments normally.

## Ownership and errors

Reflection migration preserves enum values and aligns field names and types by
their shared index. Allocation-failure checks continue to cover partial clones,
definition loading, caches, and retained state.

Zig 0.17's test allocator can grow the last allocation in a bucket depending on
heap history. `libs/core/src/testing_helpers.zig` disables resize/remap on the
backing allocator during exhaustive fault injection, forcing deterministic
relocation. The standard checker still verifies every failure index, error
propagation, and allocated/freed byte balance. Normal positive tests continue
to use the ordinary allocator, including its successful resize paths.

CAS's real-process timeout fixtures allow 500 ms for OS execution and the
intended blocked phase. Their original overall completion bounds and assertions
that both parent and child processes are gone remain intact. Production deadline
values and timeout handling are unchanged.

Ledger retains its minimal stderr-and-trap production panic callback through
`std.debug.FullPanic`. This avoids the Zig 0.17.0 `simple_panic` namespace defect
without modifying the installed standard library. Tests keep their diagnostic
panic handler; release qualification must exercise the production path too.

## Evidence and performance

Compiler comparisons must bind both toolchains and products, including their
source, target, optimization mode, workloads, and outputs. Historical sealed
driver source and serialized optimization labels retain their original bytes.
Do not reinterpret a historical `ReleaseFast` field as a new compiler command.

The one-time migration comparison retained exact source archives, compiler and
library fingerprints, identical workload drivers, raw captures, and reports.
Its nine workloads used eight alternating rounds, with three warmups and thirty
measured operations per round. Acceptance required matching workload/output
digests, at most 3% median paired latency regression, at most 2% peak-RSS
regression, and no allocation-count increase. The results below describe those
recorded artifacts; the old compiler and comparison harness are not maintained
as repository tooling. Ongoing builds and performance tooling use Zig 0.17 only.
Historical sealed driver bytes and serialized labels remain readable as data.

Use `debug` and `safe` for ownership and safety qualification and `fast` for
release behavior and performance. Keep the existing optimization-specific gates
separate from compiler non-regression measurements. Neither a new allocator nor
a compiler upgrade is, by itself, evidence of a speedup.

TigerStyle's bounded CLI allocation policy, in-memory `usize` usage, multiline
data exception, and aggregate trace compatibility remain intentional. There is
no new upstream Zig-0.17-specific TigerStyle policy to import.

Linux CI qualifies `zig build test-definition-core -fincremental`. Developers
can opt into `--watch` with that command for iterative work. Release builds keep
their existing backend and do not enable incremental compilation.

## Qualification observations, 2026-10-03

The first compatibility-only candidate exposed a roughly 5% Ledger latency
regression. CPU sampling attributed about a quarter of the workload to canonical
string scanning. A bounded SIMD escape scan preserves the original UTF-8 check
and escape bytes; exhaustive ASCII boundary cases, a separate JSON encoder,
writer-failure cases, and the canonical corpus check the transformation.

For bounded top-K projections without later exclusions, all retained rows will
be emitted. Their payload lengths therefore determine the exact final buffer
size independently of sort order. Reserving that size removes growth calls and
checks the output bound before allocation; unbounded and single-result paths
keep their existing behavior.

An apparent trace RSS regression came from fixture generation. Allocation
instrumentation measured equal parsing peaks of 1,937,361 live bytes, while
fixture-generation peaks differed. Exact-sized fixture construction on both
sides removes that measurement artifact without changing input bytes or the RSS
budget. Golden workload digests bind the old and new fixture generators.

The resulting native ARM64 comparison used baseline commit
`9c4a5584608e23cfe3b5c125b9b1e1df38b53aa2` and candidate tree
`2e0d1ea96784cf40680cc899e8b7246e6252ec6c`, with macOS 15 deployment targets and
baseline CPU settings. Each side supplied 240 timed operations per case across
eight balanced process rounds. All workload and output digests matched.

| Workload | Candidate p50 change versus Zig 0.16 |
| --- | --- |
| Ledger top-K, 16,384 rows, K=1/10/100/1000 | 24.7–25.9% lower |
| Ledger top-K, 32 rows, K=10 | 13.3% lower |
| Full trace, 8/1,024 turns | 4.0–4.6% lower |
| Summary trace, 8/1,024 turns | 48.2–49.2% lower |

All nine cases passed the declared latency and RSS gates. Allocator call counts
(allocation, resize, and remap calls) did not increase. These are measurements
of the recorded artifacts on one machine, not promises for every workload.
